# 桌面端 → Android 功能对照（v0.5.2）

对照基准：`origin/main` @ `fa4caa5`（桌面版 v0.5.2）。桌面侧的权威清单是
`app/engine/src/server.rs` 的路由表（30+ 条）与 `app/src/views/*.ts` 的界面。

Android 侧现状由 `app/android/app/src/main/kotlin/**` 与
`app/engine-ffi/src/lib.rs`（`impl TingoEngine` 导出 34 个方法，另有 3 个独立的 `fn`）共同决定。

| # | 能力 | 桌面端 | Android | 差距 |
|---|---|---|---|---|
| 1 | 录音（麦克风） | `/api/record/*` | 已有（前台服务） | — |
| 2 | 系统内录 | `/api/record/*`（macOS 系统音频） | 已有（AudioPlaybackCapture） | 需要 **API 29+**，且每次录制要过一次系统"录屏"授权；会议软件可以禁止被抓（`allowAudioPlaybackCapture=false`），此时只有麦克风那一路，界面会提示"没抓到系统声音" |
| 3 | 静音自动停录 | `autostop.rs`（5 秒窗口 RMS 门限 + 保留 30 秒） | 已有：每 tick 取两路峰值，连续 N 分钟无声自动结束并截掉尾巴 | **门限是峰值刻度不是桌面那套 dB 刻度**；未做"会议软件退出即结束"与"边录边转写算有声" |
| 4 | 转写（Paraformer + 标点 + 声纹聚类） | `asr.rs` + `cluster.rs`（流式转写 + 结束即写转写与纪要） | 已有（sherpa-onnx）；**录完自动进这场会议并开始转写，转写完若已配模型服务则接着写纪要**（同一条链只自动跑一次，已有纪要不会被覆盖） | 边录边出字**只做麦克风那一路**（系统内录那一路不进实时文字）；实时文字是最多 3 条、不可编辑的提示，最终以录完写进 `transcript.json` 的转写为准；说话人聚类已换成桌面那套谱聚类（n<20 算一人、上限 15、合并阈值 0.78、剪枝 0.022、k-means 固定种子），**唯一偏差**是谱聚类只取 256 段子采样（桌面 faer 直接分解 1500×1500，纯 Kotlin 的 Jacobi 到 256 维已是秒级）|

| 6 | 纪要生成 | `summarize.rs`（LLM API，中英两套提示词 + 自动判断会议语言 + 长会议分段提炼） | 已有（远端 API）；设置页可选**纪要语言**（跟会议/中文/英文），`auto` 按正文汉字占比判断（≥30% 算中文，与桌面同一门限），英文章节与英文自检成对使用；超过 48k 字符的转写**分段提炼再合并**，状态栏显示「分段提炼 2/5」 | 分段上限 40000 字符与桌面远端一致，但**桌面用本机 Ollama 时会按 `num_ctx` 调小到 4000–6000**，Android 不分情况恒 40000；不注入日期对照表（只给会议日期，让模型自己换算）；不做"会议时间/时长/参会人由程序填"这一步 |
| 7 | 纪要历史版本（含手工编辑纪要） | `/api/meetings/{id}/minutes/history` | 已有（详情页溢出菜单：编辑 / 历史 / 恢复 / 删除） | — |
| 8 | 纪要自检与重试 | 桌面无（只有分段提炼/合并） | 已有（`MinutesService` 的结构校验 + 一次重试） | Android 独有，不是对照项 |

## 界面复刻清单（桌面 `app/index.html` + `app/src/style.css` + `views/`）

桌面外壳是「左侧边栏 + 右侧主区」：侧栏含品牌、三条导航（新会议 / 会议记录 / 设置）、
运行中任务区、最近会议列表、环境信息块；主区按路由换。手机上没有横向空间，
导航落到底栏（已实现），其余区块要按屏幕重排，不能照搬位置：

| 桌面区块 | Android 现状 | 计划 |
|---|---|---|
| 侧栏导航三条 | 底栏三条（录制 / 会议 / 设置） | 已对齐 |
| 品牌区（图标 + Tingo 听过） | 会议库标题行 = 图标 + 名字（中文界面"听过"、英文界面"Tingo"） | 已对齐 |
| `side-tasks` 运行中任务 | 首页「进行中（N）」：会议名 + 种类 + 进度条；转写/纪要登记，会议删除即撤 | 已有；**没有已用时/阶段文字/完成态与手动消隐** |
| `recent` 最近会议 | 会议库整列即列表 | 已完成：首页"最近 3 场"卡片 |
| `env` 环境块（占用/时长/版本） | 设置页有存储一节 | 已完成：首页底部状态行（模型就绪 / 纪要服务 / 版本） |
| 拖拽导入覆盖层 | 无（手机没有拖拽）；已换成「导入音频」入口（录制页） | 已对齐 |
| `modal` 通用弹层 | 统一为 `components/TingoDialog` / `TingoConfirmDialog` / `TingoTextDialog` + `TextInputDialog`；旧的 AlertDialog 已清零 | 已对齐 |
| toast | 底部一条全局提示：失败红色停留 4.2 秒、普通 2.4 秒；会议库失败、批量失败原因、热词保存、备份/恢复结果已接入 | 已对齐；**导入失败与详情页写失败仍是页内提示** |

顺序：先把首页（新会议）与会议库的视觉对齐，再统一弹层与提示，最后做导入与引导。

已知差距（写在明处，不装作已经一致）：

- 导入只接受音频/视频文件（十个扩展名，与桌面一致）；导入后库里存的是 16 kHz 单声道 wav，
  原文件不进库（桌面保留原扩展名，解码在转写时发生）
- 引导第二步是"模型已就绪"（手机模型随包内置），桌面是"下载约 330 MB"——同一位置的两种事实
- 纪要的分段上限是固定的 48k 字符，桌面按本机模型上下文算；相对日期靠模型按会议日期换算，桌面另注入日期对照表
- 模型服务：桌面打开设置页会自动拉一次模型列表，Android 只在点「拉取模型列表」时拉
  （省流量，也算一种"测试连接"）；桌面"测试连接"还会校验模型名是否存在，Android 只报连通性
- 会议库位置：桌面能选任意目录，Android 固定（`getExternalFilesDir` 下的应用私有目录，
  "文件"App 里看得见，额度随应用卸载清掉）——这是分区存储的直接后果
  （SAF 给的是 uri，不是可以传给引擎的路径）；要搬家请用"备份会议库 / 还原"
- 自动停录：桌面还会把"边录边转写出了新文字"当成有人说话，Android 没有流式识别，这一路缺席；
  录音过程中改设置不生效（下一场才按新值，桌面每 5 秒重读配置）
- 运行中任务登记"转写""纪要""导入"：桌面对应的是 `process` 任务，状态文字随阶段变
  （"正在保存"→"正在转写"），Android 只写"导入中"；桌面任务列表还包括模型下载与录音本身，
  Android 前者只在详情页显示、后者由前台服务通知承载
- 引导第三步的"试录 3 秒"只测麦克风：系统内录在 Android 上每次都要过系统"录屏"授权，
  引导里弹这个框只会让人困惑，所以留到录音页真正需要时才问（桌面一次回报两路）；
  麦克风失败时不区分"被拒绝"与"设备被占用"（桌面按状态码分开报）
- 引导的"接着走"入口在设置页（「继续新手引导」），桌面也放在设置页（`#/welcome/llm` 直接跳到大模型那一步）；
  Android 记住的是**离开时的那一步**，不一定正好是大模型
- 导出仅覆盖"当前版本"，桌面还能导出某个历史版本（`?version=`）
- Android 的 PDF只有文字排版，没有品牌页眉页脚，也没有鱼骨图示意（桌面用 HTML/CSS 画）

进度：首页的「最近 3 场」与「环境块状态行」已完成（`RecordScreen` 的 `RecentAndStatus`，
状态由 `AppContainer` 的模型/服务/版本实际状态得出，真机用例 `HomeScreenInstrumentedTest` 把关）。
