# Design

## Context

正式界面由 `TingoRoot` 和五个独立的 Compose 页面组成；页面以现有 ViewModel 状态和回调连接真实功能。`TingoTheme` 已提供 Tingo 浅色/深色调色板、系统字体和尺寸令牌，`MainActivity` 统一处理语言、系统主题、窗口宽度及安全区域。获批的 11 屏预览位于 Debug source set，包含样例数据，不适合作为生产界面的数据或交互实现。

## Goals / Non-Goals

**Goals:**

- 在正式 Compose 页面复用获批的纸白底、Tingo 蓝、细分隔和清晰层级。
- 延续现有屏幕状态、ViewModel 回调、五步引导、语言、系统主题和自适应导航。
- 通过已确认的公开 UI 测试边界防止内容、状态和操作回归；用测试机截图核对视觉效果。

**Non-Goals:**

- 不移植预览中的演示数据、切屏工具栏或语言/主题调试开关到正式版。
- 不更改录音、转写、纪要、会议数据、API、系统权限或 ViewModel 业务规则。
- 不添加 Apple Watch、iCloud 等 Android 不支持的功能，也不新增截图测试依赖。

## Decisions

1. **以 `TingoTheme` 作为样式的唯一来源。** 页面优先使用现有颜色、字阶、间距和形状令牌；仅在多屏出现明确共性时扩展令牌或共享组件。这样让系统明暗主题和中英文共用同一套语义。逐页硬编码颜色与尺寸容易造成主题失配和页面漂移。
2. **改造现有正式页面的呈现层，不复制 Debug 预览。** `OnboardingScreen`、`RecordScreen`、`LibraryScreen`、`DetailScreen`、`SettingsScreen` 继续接收现有状态与回调；共享组件放在 `ui/components`，页面继续负责自己的内容组织。预览页面只作为视觉参考，避免样例状态替代真实业务状态。
3. **保留 `TingoRoot` 的响应式导航与 Activity 的系统集成。** 窄屏继续用底部导航和单栏详情；宽屏继续用侧栏及列表/详情并排；安全区域、系统主题与应用语言仍由现有宿主处理。固定复刻 iOS 底栏会损失已存在的宽屏布局。
4. **按页面垂直切片采用 Compose UI 测试。** 已确认的 seam 为 `MainActivity/TingoRoot` 与五个公开屏幕 Composable。测试通过公开语义观察关键内容、状态和操作；像素级颜色、间距、排版通过测试机截图检查，不增加 Golden/Screenshot 测试框架。现有 ViewModel 单测继续覆盖业务规则。
5. **保留 Android 能力边界。** 设置页重排时只展示当前 Android 已有配置；不复制 iOS 专属项目，也不新增应用内主题切换。

## Risks / Trade-offs

- **纪要、转写与设置子页内容很长** → 保留可滚动内容区，让标题、操作和底部播放条不与系统栏或彼此遮挡；在真机上检查主要状态。
- **中文、英文及系统字体缩放后的行高和宽度不同** → 使用可换行的内容布局、保留现有本地化资源，在两种语言和窄屏下做 Compose 断言与截图复核。
- **录音或播放状态有持续副作用** → 页面改动只接现有 UI 状态与回调，不把 ViewModel 或后台服务移动到可见页面生命周期内。

## Migration Plan

1. 先为一条公开 UI seam 写失败测试，再按页面逐片实现并立即使该测试通过；不把所有测试集中写在实现之前。
2. 完成所有页面后运行相关 JVM/Compose 测试与 Debug 构建，在连接的 Android 测试机检查引导、录音、会议库、纪要详情和设置的浅色/深色画面。
3. 本变更不迁移数据或设置；回退时恢复 Compose 页面与主题组件即可，不影响会议文件和应用偏好。
