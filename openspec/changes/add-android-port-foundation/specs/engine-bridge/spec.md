# Spec Delta

## Purpose

引擎桥接定义 Kotlin 界面层与 Rust 引擎之间的契约：哪些能力可用、数据如何无损跨越语言边界、失败如何被表达与隔离。它让"ASR 在 Kotlin、会话与纪要逻辑在 Rust"的分工有明确边界，而不是一堆散落的 JNI 调用。

## ADDED Requirements

### Requirement: 能力探测

引擎 SHALL 在初始化后向界面层报告引擎版本与能力矩阵，能力矩阵 MUST 至少覆盖：会议存储读写、转写文本解析、纪要解析、鱼骨图解析、说话人命名、术语抽取。界面层 SHALL 依据能力矩阵隐藏不可用功能的入口，而不是让用户触发后才失败。

#### Scenario: 报告版本与能力

- **WHEN** 应用启动并完成引擎初始化
- **THEN** 界面可读取到非空的引擎版本字符串与包含上述六项能力键的能力集合

#### Scenario: 能力缺失时隐藏入口

- **WHEN** 能力矩阵中不包含纪要解析能力
- **THEN** 会议详情页不展示纪要页签名，且不发起相应调用

### Requirement: 数据跨边界无损

引擎桥接 SHALL 以结构化类型在 Kotlin 与 Rust 间传递会议元数据、转写文本与纪要内容，往返后 MUST 保持字段值完全一致，包括多字节中文文本、空集合、缺失的说话人别名与毫秒级时间戳。

#### Scenario: 中文与时间戳往返一致

- **WHEN** 一段包含中文文本、说话人别名与毫秒时间戳的转写数据经由桥接往返一次
- **THEN** 返回结果与原始数据逐字段相等

#### Scenario: 缺失字段默认可表达

- **WHEN** 传入的会议元数据未包含标签与标题
- **THEN** 桥接返回缺省值而非报错，且不产生空指针或未定义值

### Requirement: 结构化错误语义

桥接 MUST 把失败表达为带类别与消息的结构化错误，类别至少区分：输入非法、资源缺失、格式损坏、权限不足、内部错误。界面层 SHALL 依据类别选择提示文案，不得直接展示原始英文堆栈。

#### Scenario: 损坏文件映射为格式损坏

- **WHEN** 请求解析的 `transcript.json` 内容不是合法 JSON
- **THEN** 桥接返回格式损坏类错误，界面显示本地化提示且不崩溃

#### Scenario: 不暴露内部堆栈

- **WHEN** 任意桥接调用返回内部错误
- **THEN** 展示给用户的文案中不含 Rust 模块路径、文件行号或英文 panic 文本

### Requirement: 取消与并发

桥接 SHALL 支持并发调用，且任意落地为长任务的调用 MUST 可被取消；取消后 MUST 在 1 秒内返回且不得继续占用线程或产生后续回调。

#### Scenario: 取消长任务

- **WHEN** 界面在解析一个大型会议库的过程中发起取消
- **THEN** 调用在 1 秒内返回取消结果，且此后不再有该调用的进度回调

#### Scenario: 并发调用互不干扰

- **WHEN** 界面同时发起两次独立的会议解析调用
- **THEN** 两次调用各自返回自己的结果，数据不串扰

### Requirement: 崩溃隔离

引擎内部发生的 panic MUST 被边界捕获并转换为内部错误返回给界面层，不得终止应用进程。

#### Scenario: 引擎 panic 不杀进程

- **WHEN** 某次桥接调用在 Rust 侧触发 panic
- **THEN** 应用进程继续存活，界面收到内部错误类别，其他功能仍可正常调用

### Requirement: 原生库打包与 ABI

原生库 SHALL 随 APK 以 `arm64-v8a` 提供，并在不支持该 ABI 的设备上 MUST 在启动前给出明确不支持提示而不尝试加载。

#### Scenario: 设备 ABI 受支持

- **WHEN** 在 arm64 设备上安装并启动应用
- **THEN** 原生库加载成功，能力探测返回可用

#### Scenario: 不支持的 ABI 提前提示

- **WHEN** 应用被安装到不支持 arm64-v8a 的环境
- **THEN** 应用显示不支持提示，不执行原生库加载
